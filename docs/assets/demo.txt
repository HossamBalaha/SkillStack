EXAMPLE 1 — academic-research theme
──────────────────────────────────────────────────────────────────────────────

$ User: "Draft a methods section in LaTeX"
↓
[maestro] routing...
    │
    ├─ keywords matched: manuscript, latex, draft, section
    ├─ theme candidate:   academic-research   (score 9)
    ├─ theme candidate:   style-integrity     (score 3)  ← secondary
    └─ theme candidate:   visualization       (score 1)
    │
    → THEME: academic-research
    → SKILL: journal-manuscript-writer        (matched on: latex, manuscript, section)
↓
[skill loaded] academic-research/journal-manuscript-writer/SKILL.md   (~2,100 tokens)
↓
[agent follows workflow]
    1. Confirm target venue and document class (e.g., IEEEtran, elsarticle).
    2. Draft the methods section using only \section and \subsection.
    3. Wrap every equation, table, and figure with "% ====== %" separators.
    4. Use \cite{} (IEEE numbered style); group multi-cites sorted ascending.
    5. Cross-check every \label{} has a matching \ref{} or \eqref{}.
↓
[output] LaTeX methods section saved to manuscript/methods.tex
         (style: LaTeX, separator comments applied, IEEEtran-compliant)

  ⤷ next skill chain (if requested):
       style-integrity/latex-style-guard         → enforce typography
       writing-citation/bibtex-citation-manager  → verify bibitems cited

    ├─ theme candidate:   writing-citation      (score 2)

    │

[skill loaded] ai-output-judgement/hallucination-detector/SKILL.md   (~2,320 tokens)
↓
[agent follows workflow]
    1. Extract candidate entities: spaCy en_core_web_sm + regex for DOIs, URLs,
       version strings, and API-shaped tokens (package.Class.method).
    2. Classify each entity: person, organization, paper/DOI, library, API method,
       statistic, quote, law/regulation.
    3. Verify per type:

    6. Emit flagged spans with offsets, type, evidence, and severity.
↓

           • [S2] "Schmidt Foundation"                    → likely "Schmidt Futures"

HOW ROUTING WORKS
──────────────────────────────────────────────────────────────────────────────

1. The maestro (skills/maestro/SKILL.md) reads the task description.
2. It tokenises the text and matches each token against the 9-theme keyword
   table (academic-research, style-integrity, ml-engineering, data-engineering,
   visualization, writing-citation, ai-text, ai-output-judgement, project-tooling).
3. The highest-scoring theme becomes the primary theme. The agent then picks
   the 1–3 skills inside that theme whose name/description overlap most with
   the task tokens.
4. The chosen SKILL.md is loaded and its workflow is followed step-by-step.
5. If the task naturally chains (e.g., draft manuscript → enforce LaTeX style
   → verify citations), the maestro loads the next skill after the first one
   produces its output. Themes are independent — drop or rename any of them
   and the routing still works.

The same flow is available programmatically via the SkillStack MCP server:

    route_task("Draft a methods section in LaTeX")
    → { top_theme: "academic-research",
        suggestions: [{ skill: "journal-manuscript-writer", ... }] }

Install:  cd skills/mcp-server && npm install
Run:      npm start
Register: see skills/mcp-server/README.md for Claude Desktop / Cursor configs.
