# Sphinx Docs Builder

## When To Use
- You need a hosted API reference site for a Python package.
- You want tutorials and how-tos alongside autogenerated API pages.
- Your docstrings follow Google or NumPy style and you want `napoleon` to render them.
- You prefer Markdown over RST and want MkDocs Material as an alternative.

## Workflow
1. Install docs deps: `sphinx`, `furo` (RTD-style theme), `myst-parser`, `sphinx-autodoc-typehints`.
2. Run `sphinx-quickstart docs` to scaffold `conf.py`, `index.rst`, and `Makefile`.
3. Edit `conf.py`: set `project`, `author`, `version`, `extensions`, `html_theme = "furo"`.
4. Add extensions: `sphinx.ext.autodoc`, `sphinx.ext.napoleon`, `sphinx.ext.intersphinx`, `sphinx.ext.doctest`, `myst_parser`.
5. Configure `intersphinx_mapping` to point at Python, NumPy, PyTorch docs.
6. Write `docs/index.rst` with a `.. toctree::` referencing `api/index` and `tutorial/index`.
7. Create `docs/api/index.rst` listing `.. automodule:: src.ModuleName` for each public module.
8. Create `docs/tutorial/getting_started.md` with narrative docs (MyST Markdown).
9. Add a `docs` target to the Makefile: `sphinx-build -b html docs docs/_build/html`.
10. Optionally add `.readthedocs.yaml` for Read the Docs hosting.
11. Build locally and fix warnings; warnings fail CI (`-W` flag).

## Inputs
- The package import path under `src/` (Sphinx will autodoc from there).
- Docstring style: Google or NumPy (both handled by `napoleon`).
- Theme choice: `furo` (default), `sphinx_rtd_theme`, or `alabaster`.
- Optional intersphinx targets (Python, NumPy, PyTorch).

## Outputs
- `docs/conf.py`, `docs/index.rst`, `docs/api/index.rst`, `docs/tutorial/*.md`.
- `docs/_build/html/` (gitignored) with the rendered site.
- `.readthedocs.yaml` for free hosting.
- A `make docs` target and a CI job that builds docs on every push.

## Key Rules
- Treat warnings as errors: pass `-W --keep-going` to `sphinx-build` so broken cross-refs fail CI.
- Every public module must appear in `api/index.rst` with `.. automodule::` and `:members:`.
- Use `napoleon_google_docstring = True` (or numpy) so docstrings render cleanly.
- `intersphinx_mapping` entries must point at stable inventory URLs, not `/latest/` when a pinned version exists.
- MyST Markdown files use the `.md` extension and must be listed in the toctree.
- Never commit `docs/_build/`; add it to `.gitignore`.
- The `autodoc` import path must match the installed package name; install the package with `pip install -e .` first.

## Examples
`docs/conf.py`:

```python
# docs/conf.py — Sphinx configuration for the researchkit package.
project = "researchkit"
author = "Lab Tooling"
version = "0.1.0"
release = "0.1.0"

extensions = [
  "sphinx.ext.autodoc",
  "sphinx.ext.napoleon",
  "sphinx.ext.intersphinx",
  "sphinx.ext.doctest",
  "myst_parser",
]

# Render Google-style docstrings.
napoleon_google_docstring = True
napoleon_include_init_with_doc = True

# Cross-link to external docs.
intersphinx_mapping = {
  "python": ("https://docs.python.org/3", None),
  "numpy": ("https://numpy.org/doc/stable/", None),
  "torch": ("https://pytorch.org/docs/stable/", None),
}

# Theme and HTML output.
html_theme = "furo"
html_title = "researchkit docs"

# Treat warnings as errors so broken refs fail CI.
suppress_warnings = []
```

`docs/api/index.rst`:

```rst
API Reference
=============

.. toctree::
   :maxdepth: 2

   src.DataLoader
   src.Model
   src.Metrics
```

```rst
.. _api-dataloader:

src.DataLoader
==============

.. automodule:: src.DataLoader
   :members:
   :undoc-members:
   :show-inheritance:
```

Makefile target:

```makefile
docs:
        sphinx-build -W --keep-going -b html docs docs/_build/html
```
